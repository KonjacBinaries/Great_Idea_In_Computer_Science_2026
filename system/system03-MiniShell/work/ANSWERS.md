# Basic 概念问答

## Q1：Shell、终端和普通命令程序有什么区别？

在终端中输入 `cat a.txt` 并按回车，终端把输入交给 Shell；Shell 解析命令名、参数和重定向等语法，再执行对应命令；命令程序完成读取文件等具体工作，把结果写到标准输出，终端负责显示这些字符。终端提供输入和显示界面，Shell 负责解释和组织命令，普通命令程序负责具体任务。真实 Shell 的某些命令也可以内建在 Shell 中。

本项目用同一个 C++ 程序中的函数模拟命令执行，不启动真实的 cat、touch 等程序。

## Q2：本项目的文件保存在哪里？和真实文件有什么区别？

文件保存在程序内存中的 `std::map<std::string, std::string>`：键是文件名，值是文件的完整内容。根目录 / 是约定的固定位置，不是电脑上的实际根目录，也不需要单独存进表中。

模拟命令只修改这个映射，不读取或写入电脑上的同名真实文件。程序退出后，映射随进程销毁，虚拟文件全部消失；下次启动从空文件表开始。真实文件通常由操作系统管理并保存在磁盘上，程序结束后仍可保留。

## Q3：touch、cat、echo 分别做什么？

| 命令 | 输入 | 输出 | 是否改变虚拟文件 |
| --- | --- | --- | --- |
| `touch a.txt` | 一个合法文件名 | 成功时没有输出 | 不存在就创建内容为 `""` 的空文件；重复执行保留已有内容 |
| `cat a.txt` | 一个已有文件的合法文件名 | 原样输出完整内容，不额外加换行 | 不改变；不存在时报 ERROR，也不创建文件 |
| `echo hello world` | 零个或多个文本参数 | 参数用一个空格连接，再加一个换行；无参数只输出换行 | 普通形式不改变文件；接 `> 文件名` 时创建或覆盖该文件 |

## Q4：echo hello > a.txt 中的 > 有什么作用？

`>` 将本来应显示的 echo 输出改为覆盖写入指定文件。这里写入虚拟文件表中 a.txt 对应的字符串，完整内容为 `"hello\n"`。文件不存在时创建，已存在时替换原内容。输出已经送到虚拟文件，因此这次命令不再向终端显示 hello；之后执行 `cat a.txt` 才会显示它。

## Q5：依次执行四条命令后是什么结果？

下表中的 `\n` 表示一个真实换行字符，不是反斜杠和字母 n 两个字符。

| 步骤 | 命令 | a.txt 的完整内容 | 终端输出 |
| --- | --- | --- | --- |
| 1 | `echo one > a.txt` | `"one\n"` | 无 |
| 2 | `touch a.txt` | `"one\n"`，已有内容保持不变 | 无 |
| 3 | `echo two > a.txt` | `"two\n"`，覆盖掉原来的内容 | 无 |
| 4 | `cat a.txt` | 仍为 `"two\n"` | two，随后换行 |

最终文件中只有第二次写入的 two 和换行，不会同时保留 one。
